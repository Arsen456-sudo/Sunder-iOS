# Separate centered chat title and immediate tab hiding

## Problem
Post-layout moves between navigation item groups do not reliably override SwiftUI's
trailing grouping on compact iPhone navigation. Title/avatar still share a capsule.
Tab hiding starts after SwiftUI onDisappear and then adds a native animation delay.

## Solution
Declare the title in the native principal slot and avatar in trailing at source.
Use separate official glass button styles and hide shared toolbar backings. Remove
the post-layout group migration/identity attachment. Keep existing actions/notes.
Use UIKit root lifecycle will callbacks and immediate setTabBarHidden, including
native tab selection, rather than relying on after-transition SwiftUI callbacks.

## Steps
1. Change source toolbar placements/styles and remove group migration controller.
2. Move root visibility to UIKit viewWillAppear/viewWillDisappear; scope by owner
   and navigation depth, preserving tab switches, modals and cancelled gestures.
3. Disable native tab-hide animation, keeping model and controller cache aligned.
4. Review actions, lifecycle and availability twice; update docs and compile in CI.

Threat model: presentation-only, no account/message/storage/network changes. Avoid
mutating another navigation stack or hiding the bar merely for a tab switch.
Plan review 1: principal overrides default title and removes sibling grouping.
Plan review 2: native will callbacks run before transition configuration; no timer,
custom animation, navigation-delegate replacement or private API is needed.

## Review and validation scope
Review 1: verified principal/trailing independence, no duplicate shared material,
unchanged title/profile/context actions and note/selection fallback. Removed the
post-layout group mutation controller completely.
Review 2: covered push, root return, cancelled interactive return, tab switches,
modals and owner lookup fallback; tab updates have no animation. No delegate,
timer or business-logic change. Source inventory/notices and CI compile required;
Windows cannot validate the actual iPhone appearance or UIKit lifecycle timings.

Root returns report their early visibility to the existing model rather than
forcing the bar visible while conversationOpen is still true during an interactive
back gesture. Hiding remains imperative/synchronous, avoiding a one-frame flash.

Navigation push/pop animations must remain enabled. Immediate tab-bar hiding is
scoped to the tab bar and must not disable upper-toolbar or navigation transitions.
Exact cross-placement item morphing is a device acceptance check, not established
by principal placement or matching SwiftUI item IDs alone.
