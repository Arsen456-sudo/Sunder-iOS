# Native header matching, search geometry and chat entry

## Problem
The principal SwiftUI title is not a native bar item matching the unread filter.
Its small glass sizing differs from side islands. Integrated UISearchController
competes with a separate Close bar item for width. Folders have no glass effect.
The custom tab hosting hierarchy needs explicit bottom scroll-edge ownership.
Opening a chat deliberately waits 250ms before selecting its route.

## Solution and detailed design
Use a native center UIBarButtonItem group with identifier sunder.context, owning
its hosted existing title action directly (no SwiftUI principal or trailing title
that can overwrite the group). Native editor style and native glass backing own
geometry and animation. Retain existing avatar action, enlarge image to 32pt and
assign its UIKit identifier. Forward environment to the hosted title content.
Use the search controller's own cancel control, avoiding competing right items.
Wrap the folder segmented control with actual UIGlassEffect on iOS26. Bind a
bottom UIScrollEdgeElementContainerInteraction to the chat list and native tab bar.
Remove deliberate navigation wait only for ordinary list taps; reset previous
message state before selection and keep asynchronous loading/cancellation paths.

## Steps
1. Audit ownership, data flow and availability before source changes.
2. Implement source-owned center group and independent native avatar; preserve actions.
3. Correct search cancel layout and real folder glass; bind bottom edge to list.
4. Add immediate list-entry path without changing other callback callers.
5. Update product/spec, refresh source anchors and generated inventories/notices.
6. Review twice, compile via existing CI and report device verification separately.

## Threat model and review
Presentation must not expose previous-chat messages or bypass privacy guards.
No encryption, transport, account identity or persistent-data changes. List entry
must clear old ItemsModel state before pushing; secondary and special routes retain
existing semantics. Only the owning navigation item/scroll list may be changed.
Review 1: a title source owned by UIKit avoids fighting a SwiftUI title preference;
search cancellation must still clear search/link/progress state.
Review 2: preserve Reduce Motion through UIKit, no new animation engine; clean up
only owned native groups/interactions. CI and iPhone verification remain separate.

## Implementation review
First pass found and fixed an overly broad circle-style replacement affecting
compose controls outside navigation; their existing glass is restored. Native
center sizing is cached until content/width changes, with reentrancy protection.
Second pass checked forward/back ownership, selection/note fallback, cancelled
message loads, search cancellation and hidden-list edge cleanup. Added a second
cancellation check at initial-message MainActor publication. Outgoing search/list
lifecycle callbacks cannot reinstall bottom-edge ownership after disappearance.
No custom animation, global navigation delegate or delay was introduced. Existing
business/callback routes are retained. Source checks and CI compilation are distinct
from pending device timing/visual checks; no measured latency percentage is claimed.
