# Build24 stackshot-driven profile dismissal workaround and isolated unread chrome

## Evidence before changes
Verified installed SunderSourceRef is profile-dependencies-1 (build24), not an old IPA.
User reproduced hang and left app open. Two main-thread stackshots were captured and
symbolicated with the device's own dyld cache: SwiftUI ViewBodyAccessor/GraphHost/
AttributeGraph update work, and DeprecatedAlertBridge.update(environment:) in sample2.
The thread is runnable; this is not an observed core/network wait. One state-during-
view-update fault persists. Logs have titleView=true, centerItems=0, actual trailing
Groups=1/items=1 in chat. Source match status was string-redacted, so it is unknown.
User confirms unread still merges toward compose on push/pop.
Raw logs/cache/tools remain Git-ignored. Stackshots are evidence of the mechanism,
not a symbolicated app-source line proving the entire causal chain.

## Targeted design and steps
1. Replace the main ChatInfoView/GroupChatInfoView DismissAction environment property
   with the existing presentationMode binding and a private dismiss() method. Keep
   all callers/actions, pushed/modal content, back gestures and alerts. This removes
   DismissAction from self captured by legacy alert/action-sheet closures. Do not
   repeat path/role/center-group experiments; test this specific bridge workaround.
2. Set sharesBackground=false on the semantically resolved native unread bar item,
   not on an empty legacy array and not on other working items. Retain IDs and
   existing geometry. Emit primitive source match booleans (instead of private
   interpolated String) to verify actual identity resolution on the next phone run.
3. Update product/spec and source anchors, inventory/notices; review twice and CI.
4. Reproduce on installed new build before claiming hang or title morph solved.

Threat model: presentation only, no messages/accounts/crypto/network/storage changes.
All alert confirmations, role gates and modal dismissal behavior must remain. Native
presentationMode pops a pushed profile and dismisses a modal profile. Existing helper
functions taking DismissAction are unchanged. Full filter-to-title morph is still a
known unsupported pairing in the present header architecture and not claimed fixed.
Review 1: preserve every dismiss call through same-signature private method.
Review 2: change only unread background sharing; other header materials/animations stay.

## Implementation review
Pass1: every main-profile dismiss call resolves to the same-signature private method;
other subviews/helpers keep DismissAction. Both modes retain existing presentation.
Pass2: unread background sharing is written once per item through a weak reference,
not repeatedly on every layout. Primitive diagnostics expose group size; source IDs
and other buttons' appearance remain. No routing/stack redesign was added.
Phone validation remains pending until the signed new binary is installed. No raw
logs/symbol caches/tools are included in Git. Symbolication addresses are diagnostic
observations, not proof that every iteration has the same root cause.
