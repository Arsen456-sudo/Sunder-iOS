# Chat-list-only UIKit / Liquid Glass redesign

## Problem
The maintainer narrowed the migration to the existing chat-list screen. Its top
bar hosts three SwiftUI roots, its one-hand toolbar is a full-width SwiftUI bar,
and search/filter controls use older rectangular styling. Preserve all actions,
rows, tags, search/link resolution, account switching and navigation routes.

## Solution
Replace only this screen's chrome and search controls with native UIKit. Use
UINavigationBar for the top layout, and a floating UIGlassContainerEffect with
interactive glass islands for the one-hand layout. Native controls contain no
UIHostingController. Keep the working SwiftUI list/row actions and modal content;
this is not a claim of a full screen-content or application-wide UIKit migration.

## Technical design
- Pure UIKit ChatListChromeController owns buttons, title/status, avatar badge,
  constraints, native glass, accessibility and foreground visibility callbacks.
- A small SwiftUI adapter passes current values/callbacks and retains the existing
  subscription polling/formatting; stop polling when hidden or dismantled.
- Preserve one-hand list inversion but keep chrome outside that transform.
- Bind UIScrollEdgeElementContainerInteraction to the actual root list scroll view
  through a scoped, one-time geometry-checked probe. Rebind on hierarchy change,
  restore the previous edge style on detach; no global appearance mutation.
- UISearchBar owns text editing/cancel/clear; bindings keep existing link/name
  resolution and unread filter code. Keep an explicit clear button during linking.
- iOS 26+ uses real UIGlassEffect/UIGlassContainerEffect and system edge effects.
  Older systems use platform materials, not a claimed progressive-blur substitute.
- Respect Reduce Motion/Transparency, Dynamic Type, RTL, theme and safe areas.
- Do not add unrelated tabs or change conversation/settings screens or core data.

## Steps
1. Audit main-list source, product/spec, UIKit bridges and Apple API availability.
2. Implement the native controls and wire existing actions; remove replaced hosts.
3. Adjust only main-list spacing; preserve tag editing, row/swipe behavior.
4. Update product/spec/impact and explicit remaining-SwiftUI report.
5. Review twice; compile the IPA with cached native core. Where feasible use a
   standalone UIKit simulator harness to inspect the actual chrome in both themes.
6. Report compile/visual results separately from on-device full-screen validation.

Threat model: no network, crypto, storage or permission changes; profile images
use the current decoder, no new logging of account/message data. UI callbacks must
not accidentally execute destructive row actions. Probe scope must not bind a
different screen's list or install duplicate edge effects. Plan reviewed twice for
scope, feature retention and lifecycle; full SwiftUI migration is explicitly deferred.

## Integration progress
Native chrome/search/filter wired into ChatListView and main Xcode target. Removed
three hosted toolbar roots and legacy full-width bottom toolbar. Business logic,
rows, tags, swipes and routes retained. Static review checks scoped lifecycle,
search callbacks, old-OS guards and one-hand transforms; CI compilation follows.
