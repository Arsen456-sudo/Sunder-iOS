# Native side navigation without regressing independent profiles

## Problem
Build26 profile presentation is confirmed working by the user, but opens vertically.
The source unread item still merges toward compose; its destination is a principal
titleView, not a matching UIBarButtonItem. Prior center-group rewrites hid the title.

## Solution summary
Keep each profile's original independent NavigationView and every action/child page.
Use an owned UIKit navigation container over the unchanged chat, with a transparent
root and a native push/pop of a hosting controller. Present/dismiss that container
without animation; only UINavigationController animates. Never attach a second
navigationDestination to the chat's SwiftUI stack or replace its delegate.

## Technical design
A background UIViewControllerRepresentable owns the presentation state machine and
its UINavigationControllerDelegate. Defer reconciliation out of representable update.
Push only after presentation completes. Back and all root profile dismiss handlers
use an optional environment close action to pop this owned stack. Other callers keep
their DismissAction. Child links retain the profile's independent NavigationView.
On completed pop, dismiss the transparent container, then publish false and invoke
cleanup once. Cancelled interactive pop stays open. The outer native back gesture
is available only at the profile root; nested navigation keeps its own back gesture.
Forward existing explicit chat/theme/privacy content; do not copy parent environment
DismissAction. Reduce Motion disables the outer push/pop animation.

Unread gets its own system glass surface with shared toolbar backing hidden. This
prevents it joining compose's native platter. Keep source/destination identifiers,
center title and other working items. This is isolation, NOT a claimed exact morph:
public UIBarButtonItem matching cannot target the current titleView. Preserve that
remaining gap explicitly rather than repeating the failed center-group rewrite.

## Steps
1. Read product/spec/impact and current independent profile/dismiss data flow.
2. Implement owned UIKit side-presentation and root-only close override.
3. Isolate unread's glass backing without changing actions or other header items.
4. Update product/spec/anchors, inventory, notices and SourceRef; review twice.
5. Compile using existing macOS CI; actual slide/nested/cancelled back verification
   requires signing and installing the resulting IPA.

## Threat model and plan review
Presentation must retain app-screen redaction, never capture message snapshots, and
never modify transport/storage/crypto or role gates. Closures must not retain the
owned nav/controller in a cycle; completion and teardown must be idempotent.
Review1: separate UIKit ownership preserves the working independent NavigationView;
no new SwiftUI chat-stack route, custom animator or image snapshot.
Review2: all root dismiss paths use the override, nested dismiss contexts remain local,
cleanup runs only after actual close; exact unread morph remains unimplemented.

## Implementation review
Pass1 found an inherited-close hazard in nested modal profiles; fixed by using the
close override only for fullScreen=true, preserving other modal DismissActions.
Native willShow gates repeated close requests, didShow handles cancelled gestures.
Content carries explicit observed models/privacy and no parent DismissAction copy.
Pass2: teardown and pop completion clear owned state once; all root dismiss sites
use the wrapper. Existing child views/helper DismissAction signatures unchanged.
No message/core/version/workflow changes. The filter-to-title requirement remains
open: only erroneous shared backing is isolated. Source checks and macOS compilation
are separate from device acceptance.
