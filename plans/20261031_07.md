# Persist chat navigation path and restore native toolbar identity

## Problem
User reports profile push hangs and unread/compose visually merge during push/pop.
NavStackCompat reconstructs its entire NavigationStack path from one Boolean getter;
it cannot preserve independent nested destination state. Source toolbar native IDs
are assigned, but the destination avatar assignment disappeared when the failed
center-group adapter was removed. Principal is not guaranteed to be a native item.

## Design
Use persistent @State [Bool] navigation path initialized from isActive. External
open/close only inserts root if absent or clears path; native pop to root mirrors
isActive=false. Do not synthesize the path on every read. Keep iOS15 NavigationView.
Add a presentation-only UIKit identity adapter to modern chat: assign existing
trailing avatar sunder.avatar, disable background sharing on that item, and assign
sunder.context only if UIKit actually exposes one existing center bar item. Never
create/move groups, change role or replace titleView. Log only structural counts
once (no names/messages) to distinguish actual UIKit representations. Native
principal-only filter morph remains unproven, not claimed solved.

## Steps and threat model
Read route/state flow, implement isolated fixes, update docs and source anchors,
regenerate notices/inventory, review twice, compile through CI. No network/crypto/
message data changes. Keep child profile content, privacy guards and native gestures.
Path sync must not close chat when popping only a child. Avoid arbitrary timers,
custom animations, delegate replacement, duplicate title or background material.
Review 1: stable state preserves child routes; external false still resets chat.
Review 2: match only actual existing bar items; structural diagnostics expose no PII.
Device reproduction and console evidence remain necessary for final validation.

Source review also found synchronous apiGetGroupLink in the group profile's main
onAppear. Add an async wrapper using the existing async chatApiSendCmd path with
identical result/error mapping; load it in a cancellable task keyed by group ID.
Preserve permissions and guard cancellation/group identity before publishing. This
prevents waiting on the core command queue from blocking the profile push animation.

Implementation review 1: stable path handles initial active route, root pop, external
close and profile child pushes without overwriting the full stack. iOS15 fallback
is untouched. No raw user data enters structural logging.
Implementation review 2: async group link keeps identical command/error mapping,
permission gate, task cancellation and group-ID check. Native item identity updates
only existing items; there is no role/group/layout change. Filter-title morph is
still conditional on actual native representation and must not be claimed verified.
Available local device-log executable/package discovery found no reader, so no live
iPhone log capture or reproduction is claimed. Source checks and CI remain separate.
