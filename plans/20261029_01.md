# Fix launch without an entitled App Group

## Problem
Two USB crash reports from 2026-10-29 show SIGTRAP in getAppDirectory(), called by
getWallpaperDirectory() during AppDelegate.prepareForLaunch(). The group-container
lookup is force-unwrapped but returns nil after sideload signing without access to
group.chat.simplex.app. The UI is never reached.

## Solution
Cache the actual optional App Group URL. Use the existing documents-database mode
and app-private defaults when the group is unavailable. Remove the force unwrap
from the path helper used by wallpaper/IPC setup. Keep entitled installations on
their current shared paths. NSE and Share Extension must refuse database work if
they cannot access the shared container, rather than create isolated extension DBs.

## Technical design
AppGroup.swift exposes appGroupContainerURL; groupDefaults uses the group suite only
when this URL exists. FileUtils returns documents as the unavailable-group path
fallback. SimpleXApp.setDbContainer selects .documents and .postponed (existing
non-migrating legacy mode) on fresh sideloads. Preserve interrupted migration states
so this change does not discard an export/import recovery step. NSE delivers the
original notification on unavailable group. SE shows an explanatory error with a
working completion callback before loading any shared content or opening a DB.

Threat model: no access to another app's container is attempted; no encryption,
Keychain protection or signature validation is weakened. Extension fallback must
not manufacture separate chat databases or expose a different profile's messages.
Existing databases are not deleted, moved or automatically migrated.
