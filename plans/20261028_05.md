# Avoid repeated compiler bootstrap in iOS CI

## Problem
The first device job is building GHC and its runtime from source. The workflow did
not configure the haskell.nix project's documented signed binary cache. Also the
native archive cache was only saved by a successful job's post step; a later Swift
failure could discard hours of completed native work.

## Solution and technical design
Add cache.iog.io as an extra substituter with its documented hydra.iohk.io signing
key, preserving default caches, signature checks and the locked source inputs.
Restore the exact native archive key with actions/cache/restore and explicitly
save it after archive-name validation, before any Swift package/Xcode work.
Keep the existing key so a successful in-flight job's result remains reusable.
Do not cancel, restart or claim to alter the already running job. No unversioned
download of application libraries, no unsigned Nix substitutes and no paid service.

## Steps
1. Verify official cache guidance at the locked haskell.nix revision and endpoint.
2. Update the device workflow and build documentation in private/public checkouts.
3. Review twice: exact key, early save ordering, immutable action pin, signatures,
   unchanged locked core inputs, existing job unaffected.
4. Commit and push main; do not trigger a second full build just to test caching.

Threat model: build dependencies are executable inputs; only the upstream project's
documented signing key is added, and require-sigs stays enabled. Cache miss is still
possible; no fixed speedup or availability of every compiler artifact is promised.
Product behavior is unchanged. Build details belong to spec/architecture and README.
