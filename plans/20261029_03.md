# Compact chat-list controls and server-information screen

## Problem
The maintainer requests plain tappable Chats text over the scroll-edge blur,
smaller side islands, and the same native design on the server-information modal.

## Solution
Keep the shared native chrome, remove the central material in both placements,
reduce the default circle from 56 to 44 points, and use a 60-point toolbar.
Reuse that controller for the server modal's close/title/share controls. Move its
profile/type selectors above the statistics as native segmented controls. Keep
statistics, server links, sharing and destructive confirmations intact.

## Technical design
Add display-only symbols, accessibility labels and enablement to chrome state.
Server chrome has a noninteractive title; Chats remains tappable. Each screen
has its own weak scroll binding; no cross-modal sharing of scroll views. Native
segmented control bindings preserve the existing four summary branches. Retain
SwiftUI statistics and rows; no full-screen UIKit migration claim. Child server
pages retain the system navigation bar and back behavior.

## Steps
1. Update compact shared header and keep the middle surface transparent.
2. Add native server-header and segmented-control adapters; wire modal actions.
3. Preserve List contents and all existing network/statistics functions.
4. Update product/spec/source anchors and impact index, review twice, build IPA.

Threat model: server details/JSON stay local until the existing explicit Share
action. No additional logging or requests. Reset/reconnect retain confirmations.
Review the plan for navigation, empty/loading states, disabled sharing, Dynamic
Type, old OS fallbacks, and independent scroll binding. Two plan passes found no
additional scope or data-flow issue.
