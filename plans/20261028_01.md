# Temporary removal of bundled branding

## Problem statement

The maintainer has authorized removing logos while preparing Sunder for publication.
Removing required packaging resources outright can break icon catalogs and generated MR
identifiers. Branding also appears in QR overlays, operator buttons and spoiler textures.

## Solution summary

Remove logo artwork from the application resource sets and replace logo-only controls with
text or existing system/network symbols. Required app-icon slots temporarily contain plain
color fields, not a new brand. Preserve names, conditions, attribution and all network data.
This stage covers bundled applications, not the entire historical website/blog artwork.

## Detailed technical design

- iOS: remove unused logo, operator-logo, watermark and CallKit-template image sets;
  use provider names for operator actions, a standard network symbol in small rows,
  and CallKit's default appearance. QR codes retain all generated modules with no overlay.
- Spoiler foreground hiding and reveal handlers remain unchanged; only the decorative
  watermark overlay is removed. No hidden message text becomes visible through this change.
- iOS and Android launcher/preview bitmaps retain their exact required dimensions with
  neutral opaque fills. Android adaptive foregrounds contain no branded drawing.
- Kotlin welcome/call headers use app_name. QR generation and exported QR bitmaps both
  omit logos. Generated image names referenced by metadata retain empty SVG slots where
  needed; operator controls show names instead of empty logo-only hit targets.
- Desktop packaging falls back to platform defaults. Tray markers become basic status
  rings with the unread dot retained, so the tray remains discoverable and functional.
- Preserve original resource hashes and classify deletion/substitution in a stage manifest.
  Original licenses and operator conditions remain unchanged. Git history is retained.

Threat model: avoid revealing concealed message text, altering QR/link payloads, obscuring
operator identity, breaking launcher/notification resources, or falsely claiming that old
artwork has vanished from history. The change adds no services, permissions or data flows.

## Detailed implementation steps

1. Inventory exact logo resources, callers and required packaging slots.
2. Apply presentation-only changes without changing handlers, storage or server acceptance.
3. Delete obsolete artwork and create minimal technical resource substitutes.
4. Update product/spec/concept/impact and publication records.
5. Review structured resources, catalog references, QR/spoiler paths and protected notices;
   repeat review until two consecutive passes find no new issues. No builds/tests requested.
6. Commit and push the private preparation branch; do not change public visibility/history.

Affected iOS documents: product/views/{onboarding,new-chat,chat,settings,call}.md,
product/concepts.md, spec/impact.md, spec/client/{navigation,chat-view}.md,
spec/services/{calls,theme}.md and spec/architecture.md. No product flow is reordered.
