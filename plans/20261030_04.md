# Native control geometry and search correction

## Problem
Device feedback: toolbar buttons are not circular, the avatar follows a square
profile preference, search uses a generic field, menu rows inherit blue tint,
and the conversation has an opaque top band.

## Solution and design
Use real UIKit UIButton glass configurations in fixed 44-point circles and
UISearchBar for the shared search adapter. Hide only the redundant toolbar
backing for those UIKit buttons on iOS 26. Preserve older-OS controls. Scope
neutral label colors to navigation rows and compose controls; retain semantic
warning/destructive colors and theme settings. Let the conversation scroll
beneath the system navigation bar without removing safe content insets.

## Steps
1. Read search/focus/link and button action flows, preserve all bindings.
2. Implement UIKit adapters in the existing registered source file.
3. Route list/contact/member/chat searches through the adapter.
4. Correct row colors and conversation layout; update product/spec/inventory.
5. Review availability, focus, permissions and diff twice; compile in CI.

Threat model: UI-only; no network/storage/auth changes or new logging. Search
cancel must not trigger a connection, and disabled/link states must block editing.
No gesture replacement for voice recording. No claim of iOS 27/device verification
without an available SDK/device test.

Plan review 1: preserve live focus, link progress and deferred sheet routing.
Plan review 2: all new APIs availability-guarded; no nested glass backings.

Review correction: preserve literal UTF-8 resources and repository LF; keep filtered
search placeholders localized, circular avatar pixels untinted, unread indicator
independent of avatar availability, and avoid nested toolbar glass in one-hand mode.

Final review 1: original profile/compose and unread actions, hidden-profile filtering,
link resolution and voice gesture handlers are retained. UIKit APIs are guarded at
iOS 26, with iOS 15-supported fallback configurations. Image decode is cached.
Final review 2: explicit semantic UIColor.label prevents Button tint inheritance;
no extra glass backing, authentication or business-logic change. Source/notice
checks pass; visual acceptance and real-device safe-area behavior remain unverified.
