# Floating system-glass composer and system symbol refresh

## Problem
Chat composer still uses a full-width bar background, an opaque editor, and action
controls overlaid inside it. The requested design needs independent floating glass
field/actions and a native progressive bottom edge. Header matching is a separate
known API/ownership gap: source UIBarButtonItem versus principal titleView.

## Solution and technical design
Keep all compose/send/voice/live/draft/preview/permission logic. On iOS26 split the
existing SendMessageView editor and action area into sibling islands. Editor uses
native glassEffect with rounded multiline shape, actions retain handlers/gestures
inside native interactive glass. Older OS keeps existing layout. Remove only the
modern full-width bar/divider; retain grouped context/attachment previews in glass.
Use safeAreaInset for bottom controls on iOS26, allowing content behind floating
controls while retaining safe content insets and keyboard avoidance. Register an
actual UIScrollEdgeElementContainerInteraction for .bottom against ChatView's real
EndlessScrollView; no synthetic gradient/opaque blur overlay or duplicate effects.
Keep selected-message toolbar functional and respect existing disabled states.

Use system SF Symbols from the device OS, with checked names/fallbacks; do not
claim a symbol's introduction date equals better design. Main/settings/tab icons
remain semantic, avatar tab stays the user's photo. No downloaded icon packs.
Header exact morph decision requested asynchronously: retain native/centered title
or allow narrow custom interpolation. No repeat of known broken center-item adapter.

## Implementation steps
1. Trace body/send/editor/buttons/preview/scroll and tab/settings symbol paths.
2. Add shared native compose surfaces/edge binding; isolate modern layout branches.
3. Update system symbols and preserve old-OS fallback, accessibility and handlers.
4. Resolve header scope from user response, or retain native behavior explicitly.
5. Update docs/anchors/notices/inventory; two review passes and existing CI compile.
6. Verify keyboard, long text, attachments/reply/edit/voice/live and RTL on device;
   source review or compilation alone does not establish visual/runtime correctness.

## Threat model and plan reviews
No transport, cryptographic, storage, account, sending or membership changes.
Never allow disabled send/record/attach actions through glass containers. Privacy
redaction remains. Do not snapshot chats. Edge ownership must release on removal.
Review1: separate only presentation; no new recording gesture implementation or
send state reconstruction. Keyboard and selection remain bound to same editor.
Review2: progressive effect uses exact scroll instance, safe insets retain last
message reachability; legacy paths/secondary/chat-connect actions preserved.

## User scope decision
User selected: preserve native animations and centered title; defer exact unread
filter-to-title morph. Header identity/geometry/transition is not changed in this
iteration. Only source symbol rendering uses the native SF Symbols configuration.

## Implementation review
Pass1 found the shared-input/legacy-layout hazard: floating defaults false and
ComposeView alone opts in. Plain arrow/checkmark glyphs are gated by actual modern
layout, not just the opt-in flag, preserving iOS15–25 symbols/overlay. Progress still
shows even when the normal action is hidden. Existing recording gesture and timed
message menus remain. Preview hidden/empty branches retain their content gates.
Pass2 checked callbacks, action enablement, privacy and iOS availability. Modern
edge binding uses exact scroll instance and detaches on removal; no viewport/offset
engine change or guessed hierarchy search. Main profile photo and tab/header routes
are unchanged. Source inventory/checks pass; macOS compile and actual device
keyboard/scroll/voice/Dynamic Type checks remain separate and must not be conflated.
