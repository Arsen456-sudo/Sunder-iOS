# Native glass controls across the requested messaging surfaces

## Problem
The maintainer requests visible glass on server selectors and chat-folder buttons,
a black server-information background, adaptive primary header symbols, and the
same visual language for the avatar menu, conversation and contact/group profiles.

## Solution
Share UIKit glass surfaces and a native glass segmented control, preserve existing
SwiftUI data-driven content, and update only presentation/controls. Do not replace
message rendering, transport, storage, account switching or permissions.

## Technical design
- UIKit UIVisualEffectView/UIGlassEffect with accessibility and older-OS fallback.
- Native equal-width segment buttons with a nonglass active selection indicator;
  existing selection bindings and all four summary branches remain authoritative.
- Native header symbols use adaptive label color rather than the app accent.
- Server root has a black backing and a dark interface so text stays readable.
- Avatar menu keeps its account-loading/actions and gains shared rounded surfaces.
- Conversation uses the current OS navigation material and floating compose
  surfaces, retaining editor, gestures, previews, selection and call menus.
- Contact/group profile roots reuse the native compact modal header; native system
  navigation remains available for all existing child destinations. Profile actions
  retain labels, permissions and callbacks; grouped information stays nonglass.

## Steps
1. Add/register shared native design components and update server/filter controls.
2. Update folder styling, avatar menu, conversation chrome/compose, profile roots.
3. Verify action/data-flow preservation and accessibility/availability paths twice.
4. Update product/spec indexes and source anchors; build the exact tagged revision.

Threat model: no new requests or logging, no image/message caching outside existing
scope. Do not intercept message, voice-recording or row gestures with background
views. Glass backgrounds must ignore input; buttons own their existing actions.
Destructive confirmations and feature/role gating remain intact. Both plan review
passes check scope, routes, disabled states, light/dark contrast and old OS guards.

## Review corrections
- Preserve the call button's disabled *appearance* without suppressing its callback:
  that callback explains why calls are unavailable. Outer permission disablement
  on other actions remains unchanged.
- Subtract inter-button gaps when sizing profile actions; use the actual group
  action count, preventing overflow at narrow widths.
- Use UIKit cornerConfiguration on iOS 26 for glass geometry, rather than only
  clipping a rectangular material. Source: Apple UICornerConfiguration documentation.

## Static verification
Two subsequent reviews found no remaining data-flow or scope issue. Compared the
unchanged conversation renderer/action functions, send/recording state handlers,
call gating/explanation code, account load/switch paths and server summary branches
against the previous revision. Verified main-target registration, old-OS guards,
nonintercepting surfaces and generated notice hashes. Full UIKit/SwiftUI typecheck
and device appearance still require CI compilation and on-device validation.
