# Replace bespoke presentation with the actual Appearance components

## Problem
Device feedback confirms that global styling did not replace bespoke layouts.
The maintainer explicitly requires the same standard components and construction
as AppearanceSettings across menus and navigation, rather than a glass imitation.

## Solution
Replace avatar-menu stacks/cards with NavigationView + List + Section + Button.
Use native toolbars on chat-list/profile/server roots. Replace custom selectors
and search wrappers with standard controls where state/actions can be retained.
Keep message/media/voice content and security/business handlers intact.

## Design and steps
1. Native avatar List owns scrolling; remove outer sheet ScrollView nesting.
2. Preserve visible-profile filtering, switching, theme gestures and delayed routes.
3. Restore standard navigation bars/toolbars for main/profile/server roots and use
   standard Pickers in server information. Keep old-OS paths where needed.
4. Remove redundant glass backgrounds and fixed toolbar-title widths in chat;
   use native button styles, retaining editor/recording/menu behavior.
5. Update documentation/inventory, review action preservation twice and compile.

Threat model: no new transport/storage APIs, no logging of profile/message data,
and no weakening of privacy redaction, hidden-profile filtering or disabled checks.
Do not wrap a List in another vertical ScrollView. Keep nested-sheet sequencing.
Plan review checks reference fidelity, navigation and all original action paths.

## Review corrections
- List owns avatar-menu scrolling; the system sheet directly presents it at a
  large detent. Preserve the original current-user visibility gate on other profiles.
- The extracted old-OS menu is a ViewBuilder; switching is shared without changing
  the original API/error handling. Chat explicitly owns visible native navigation.
- Removed unused custom chrome/controller, selector, probe and glass backings.
- Profile-confirmation sheets preserve images, badges and callbacks; explicit choice
  is retained with modal interactive dismissal disabled and a once-only weak bridge.

## Static checks
Reference AppearanceSettings is unchanged. Account-switch operations and current/
hidden-user gates were retained; server summary branches and voice/send actions
were compared against baseline. Custom chrome/probe/selector symbols and their
Xcode registration are gone. Main and extension targets now share SystemInterface.
Source inventory has 186 files and matches normalized hashes. A two-line adaptive
chat title replaces the fixed-width/three-line layout. UI compilation and actual
device appearance remain separate checks; no 100% visual claim is made.

Two final review passes found no further scope/action-flow issue after the fixes.
Source checks confirm no remaining custom glass/controller/probe implementation,
unchanged reference and core callbacks, correct app/extension target registration,
resolved current spec links, and fresh inventory/notices. Device appearance remains
unverified until this exact compiled build is installed.
