# Main tabs, explicit search and user-managed folders

## Problem
Main chrome has misaligned symbols, oversized rows, always-visible search and
implicit type categories. Settings/profile must be independent root destinations.

## Solution
Use UITabBarController with persistent hosting roots, native search tab/action,
existing settings/profile screens and explicit environment/privacy injection.
Keep navigation/business state and auth gate outside the tab container. Use the
existing database-backed ChatTag APIs for names and multi-chat membership; do not
create folders implicitly. Pin one native segmented control above the chat List.

## Design and steps
1. Normalize UIButton image layout without changing action/hit targets.
2. Add three UIKit root tabs, avatar tab image, search action and root routing.
3. Replace top avatar with localized Edit; keep compose and status actions.
4. Show search only on request, above pinned custom folders, with explicit close.
5. Make ordinary row metrics smaller while preserving accessibility sizes.
6. Add settings folder entry and extend existing tag editor with chat selection.
7. Review profile isolation, partial-save retry, empty folders, deep links,
   privacy redaction, tab lifetime, localization and SDK availability twice.
8. Update product/spec/source inventory, compile the exact commit in CI.

Threat model: no change to auth, transport, crypto or storage format. UIHosting
roots must receive privacy redaction and model/theme/scene environments explicitly.
Folder writes must not replace other folder memberships or cross profile changes.
Preserve account management and original destinations in the full settings root.

Plan review 1: keep UI roots alive, route notification chat opens to Chats, hide
bar in a conversation. Search is an action, not a blank fourth destination.
Plan review 2: save memberships through existing APIs and surface partial failures;
retain iOS 15 fallbacks and native Dynamic Type accessibility metrics.

## Review corrections and verification
Modern tab delegates intercept Search before selection; repeated Search refocuses
without creating a fourth content screen. Tab hide animation runs on state changes
only. Each hosting root gets explicit scene/model/theme/privacy environments.
Selected-controller traversal keeps share/confirmation presentation on the visible
root. Profile/account routes removed from the old avatar entry remain in Settings.
Folder membership toggles preserve other folders, partial retry retains its ID,
and save blocks tab/back navigation. Empty/renamed/deleted folders keep All usable.
Normal row metrics shrink without changing accessibility-row sizes. Full device
appearance, safe-area and keyboard transitions remain pending installation.

Review pass 1: checked constructors/previews, native API availability and delegates,
profile boundaries, create/update/member retries, all root environments and action
routes; corrected stale toolbar/search and exclusive membership behavior.
Review pass 2: native delegates and iOS availability verified against Apple docs;
no further action-flow or scope issue found. Compile still required on macOS CI.
