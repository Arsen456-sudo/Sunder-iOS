# Fix iOS15 toolbar-builder availability and avatar-only chrome

## Problem
CI run 41209965480 fails: ToolbarContentBuilder.buildIf is unavailable on iOS15.
The modern toolbar contains an availability conditional although it is only used
on iOS26. The installed prior editor-role build may show native overflow dots.

## Solution and steps
Move availability selection to the outer ViewBuilder call site and mark the modern
toolbar iOS26-only; remove conditional ToolbarContentBuilder content. Keep legacy
routes through the existing compatibility adapter. Keep automatic navigation role,
no center groups/overflow adapter. Hide the avatar menu indicator explicitly while
preserving its long-press actions. Document, regenerate inventories, compile via CI.

Threat model: UI/availability only; no data/crypto/account changes. Review 1: iOS15
must never reference the iOS26 property outside availability. Review 2: title/avatar
stay separate; no call/search/mute context actions are removed. Actual avatar-only
appearance must be checked on device; compile success alone does not prove it.

Implementation review: verified both CI errors come from the same buildIf site.
The modern property is availability-annotated and contains no conditional toolbar
content. The availability branch is inside Group's ViewBuilder because the local
View.if transform itself is not a result-builder closure. Legacy content, privacy,
profile actions and native transitions are retained. Second pass found no further
source availability/ownership issues; CI compilation remains required on macOS.
