# Push chat profiles, enlarge avatar and remove row-entry scheduling hop

## Problem and scope
The working header must remain stable. User requests a small avatar increase,
full-page chat profiles with native back, a faster entry if safe, and filter/title
matching. The title is currently a principal titleView; native UIBarButtonItem
identifier matching cannot directly match it. Prior center-group attempts hid it
on device. Do not repeat that unverified rewrite or claim matching is fixed.

## Design and steps
1. Keep all toolbar placements/materials/animations; increase avatar 32 to 34pt.
2. Move existing direct/group profile destinations from toolbar appSheets to a root
   navigationDestination (iOS16+) / hidden NavigationLink (iOS15). Existing views
   get a pushed flag to omit their nested NavigationView and modal Done button.
   Keep same sections/actions/state and privacy/style modifiers; cleanup only when
   the destination binding returns false, not on every child disappearance.
3. Isolate NavLinkPlain on MainActor and call openChatFromList synchronously from
   the button, removing a redundant Task scheduling hop. No message-loader rewrite.
4. Update docs, refresh anchors/inventory/notices and compile. Record filter/title
   matching as unresolved until a supported native shared ownership design is proven.

Threat model: profile push must retain screen privacy and original permission checks;
no encryption/network/persistence changes. Existing modal callers keep default mode.
Review 1: native DismissAction pops pushed profile and dismisses modal profiles.
Review 2: no nested navigation container in pushed mode; same content, no cleanup on
subpage pushes. Native toolbar matching limitation must be reported honestly.

## Implementation review
Pass 1 caught escaping destination closure requirements and cleanup ordering when
chatId changes. The helper closure is escaping; group cleanup uses saved route kind.
Pass 2 checked nested profile links, native DismissAction/search, modal callers,
state/permission preservation and screen privacy. No conditional toolbar items were
added at ToolbarContentBuilder level (iOS15 availability issue is avoided).
Source checks/CI compilation and actual iPhone navigation checks remain distinct.
Filter-title matching is unchanged and explicitly not marked complete.
