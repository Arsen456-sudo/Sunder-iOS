# Restore visible chat title and shared native tab scroll-edge ownership

## Problem
The source-owned centerItemGroups title compiled but is absent on the user's
compact iPhone. Successful compilation did not establish rendering in SwiftUI's
navigation item lifecycle. Bottom edge registration lives only in main-list search
and does not cover Settings/Profile or register their content scroll view with bars.

## Solution and technical design
Restore the proven SwiftUI principal slot with a 44pt title surface using native
glassEffect, independent of avatar/back. Remove the ineffective center-group helper.
Retain native navigation animations and avatar identifiers. This restores visibility;
unread-to-title cross-placement morphing is not proven by this solution and remains
a separate limitation rather than a claimed fixed feature.
Move bottom content registration into an owned UITabBarController subclass. Discover
the selected root's visible main vertical UIScrollView (including SwiftUI ScrollView),
register it using setContentScrollView(_:for:.bottom) on selected root and tab
controller, and use bottomEdgeEffect.style=.soft. Cache the selected scroll view;
refresh at selection/layout, unregister while bar hidden. Remove search-owned bottom
interactions to avoid conflicting lifecycle ownership. No custom blur renderer.

## Steps
1. Read source/product/spec and inspect official content-scroll registration API.
2. Restore title in native principal slot and remove failed center-item adapter.
3. Add selected-root bottom scroll registration to native tab controller.
4. Update product/spec/anchors/generated files, review twice and build in CI.

## Threat model and plan review
Presentation only; no message/account/crypto/storage changes. Never bind to hidden
or unrelated roots, horizontal folder scrolling or a small nested scroll view.
Review 1: principal is the known visible path; no fallback duplicates title.
Review 2: native bars own progressive edge effects; selected-root registration covers
all tabs without special search dependencies. iPhone appearance remains unverified.

## Implementation review
Pass 1: removed the failed center-group controller and its source attachment. Only
the principal item's shared backing is hidden; avatar native glass is preserved.
Pass 2: tab-edge discovery excludes hidden/horizontal/small nested containers, caches
the chosen main scroll and clears ownership when hidden or roots change. Search no
longer installs a bottom interaction. No data/security/animation logic is changed.
Outstanding native cross-placement morph is documented as a gap, not marked solved.
Windows cannot verify actual iPhone appearance; source checks and CI are separate.
