# Sunder native chat-list bar and public source build

## Problem
The chat-list top toolbar should use UIKit navigation-bar rendering, while list,
search, profile switching, connection status and one-hand mode retain their behavior.
The maintainer also requests public source publication and an IPA build.

## Solution
Use a standalone UINavigationBar only in the root list's top safe-area inset.
Keep the existing SwiftUI controls in child hosting controllers to preserve their
bindings, status polling and sheet presentation. Leave the pushed chat navigation
and bottom toolbar intact. Do not customize UIKit bar backgrounds.

## Technical design
The representable owns its bar and navigation item; it never mutates the enclosing
navigation controller, its delegate or other screens. Hosting controllers use proper
child containment and stable identities across updates. UIKit owns item grouping.
Search removes this bar; one-hand mode uses its existing bottom toolbar.
Threat model: untrusted profile images remain on the existing image-decoding path;
this change adds no network endpoint, permissions or logging of profile content.

Publish a fresh audited export, without old private Git history. Configure public
source links and regenerate notices. Add manual CI building native libraries from
the locked Nix inputs and Xcode's unsigned device target, then package a test IPA.
No signed production or push-service compatibility is claimed.

3. Static review twice, regenerate notices and export committed source.
4. Initialize fresh public repository, preserve executable modes, push source.
