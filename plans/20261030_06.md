# System navigation integration follow-up

## Problem
Pinned controls do not extend the system scroll edge; search appears as another
row instead of integrated navigation. Toolbar symbol custom layout is unreliable,
folder deletion is hard to discover, profile title and tab root visibility differ
from the requested behavior.

## Solution and design
Use UIScrollEdgeElementContainerInteraction on the actual pinned header, attached
to its owning vertical list. Use UISearchController and UINavigationItem integrated
placement for main search, UIKit bar item identifiers for context/avatar transitions,
and native toolbar image buttons without manually resizing their imageView.
Keep existing profile/chat action handlers and all note-chat toolbar behavior.
Native grouped settings surfaces remain List/Section/Picker/Toggle controls; no
custom backdrops or control imitation. Explicit folder deletion uses existing APIs.

## Steps
1. Add delete confirmation in folder editor and handle list-delete failures.
2. Reduce segment/header height/gap and attach the native scroll edge interaction.
3. Integrate search and stable item identities into existing UIKit navigation.
4. Separate non-note chat avatar/title; keep action menus and selection mode.
5. Track root visibility per tab, hiding it only below each root.
6. Localize Profile, review ownership/lifecycles/availability twice, compile.

Threat model: no crypto/transport/storage changes. Deleting a folder only removes
the tag, never messages/chats. Child root traversal must not attach effects to an
unrelated scroll view or overwrite another screen's navigation item. Preserve
profile ownership guards, privacy redaction and disabled/call permissions.

Plan review 1: native APIs and availability checked in Apple's documentation.
Plan review 2: preserve notes, group loading, context actions, selection mode and
existing text/link search handlers. No custom animation timing or blur shaders.
